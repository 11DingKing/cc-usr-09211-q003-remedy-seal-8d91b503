# 整改证据封存数据约定

文件摘要使用 SHA-256，采集时间保留原偏移；地点为虚构示例。

data/example.json 中的记录均为虚构业务样例。字段名称与字段类型由 contracts 中的数据结构描述。原始记录按来源提供的顺序读取，字段值不在读取时改写。

## 样例记录（data/example.json）

- `measure_id` 措施编号；`site` 现场位置；`capture_at` 采集时间（保留原偏移）
- `files` 文件摘要数组：`{name, size, sha256}`

## 证据包清单（manifest）

`POST /packages` 送审后生成，内容寻址、不可改写：

- `format` 固定为 `evidence-package/1`
- `measure_id` / `site` / `capture_at`：措施与现场记录关联；`measure_id` 命中样例记录时取自记录
- `note` / `submitted_by`：送审说明与送审人
- `version` / `previous`：同一措施的版本号与上一版包编号；补交材料生成新版本
- `files` 按名称排序的 `{name, sha256, size}`；`digest` 为以上核心字段稳定序列化后的 SHA-256
- 包编号 `pkg_<digest 前 24 位>`；内容完全相同的重复送审幂等返回原包

## 复核意见

`{package_id, version, location, conclusion, reviewer, created_at}`：必须绑定存在的证据包版本与检查位置，只追加，可按包版本完整重现。

## 撤回记录

`{package_id, record_ref, reason, operator, created_at}`：现场人员撤回说明只新增记录，已封存包不被改写。

## 下载授权

`{token_id, package_id, file, issued_at, expires_at, uses}`：令牌为 `token_id.hmac`，限时有效；过期重放返回 410，伪造返回 403。下载前重算文件摘要，完整性不符返回 409，坏包不流出。
