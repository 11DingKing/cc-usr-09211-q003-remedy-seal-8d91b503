# 整改证据封存数据约定

文件摘要使用 SHA-256，采集时间保留原偏移；地点为虚构示例。

## 业务样例

`data/example.json` 由 `scripts/seed.mjs` 确定性生成，原始字节位于 `data/raw/`。每条记录把**措施、现场记录、检查位置与文件摘要**关联：

- `measure_id` / `measure`：整改措施编号与内容
- `site`：检查位置（`name` 名称、`code` 编号，可选经纬度）；复核意见必须绑定到同一结构的位置对象，不接受只有文字的“现场”
- `capture_at`：采集时间，带原时区偏移，读取与封存均不改写
- `files[]`：`name` 文件名、`path` 原件相对路径、`size` 字节数、`sha256` 整文件摘要，另以 `media/role` 区分现场照片、现场记录与文件摘要材料

原始记录按来源提供的顺序读取，字段值不在读取时改写。

## 送审与封存

送审建包时，每个文件额外申报 `chunk_size` 与 `chunks[]`（逐块 SHA-256，块为定长、末块取余长）。整包摘要按 `contracts.canonicalJSON`（键排序、无多余空白）对措施、位置、采集时间、补交关系与文件摘要清单求 SHA-256，包编号取摘要前 20 位。摘要只绑定业务内容与文件摘要，不绑定时间戳，因此同一内容重复送审得到同一编号（已封存时返回 409 提示另建补交包）。

封存清单 `manifest.json` 为 canonical JSON，附 `manifest.sig`（HMAC-SHA256，密钥存于存储根目录 `secret`）。撤回与复核记录追加在包内 `records.jsonl`，全局审计事件追加在 `events.log`；任何已封存字节与清单都不被改写。

## 票据

授权票据字符串为 `base64url(payload).base64url(HMAC)`，载荷 `{pkg, jti, iat, exp}`；`jti` 一次性，`exp` 为绝对毫秒时间戳。
